# 学園タイピングローグライク

GitHub [Epic #27](https://github.com/sato0825/school-rg/issues/27) に沿って開発中です。開発基盤 [#1](https://github.com/sato0825/school-rg/issues/1) とドメインスキーマ [#2](https://github.com/sato0825/school-rg/issues/2) を整備しました。戦闘は未実装です。カード名の直接入力を戦闘の核として実装します。

## 開発

Node.js 22 と npm を使用します。

```sh
npm ci
npm run dev
```

## 検証

```sh
npm run lint
npm run typecheck
npm run test:unit
npm run test:integration
npm run build
npm run test:e2e
npm run check
```

E2E は Chromium が必要です。未導入の場合は `npx playwright install chromium` を先に実行します。CI は PR と main への push で clean install、Chromium 導入、`npm run check` を実行します。`check` は失敗した検査で終了します。

`src/domain` はゲーム規則、`src/ui` は表示とブラウザ入力、`tests` は単体・統合・E2E を分けています。確定していない仕様は [#26](https://github.com/sato0825/school-rg/issues/26) で設定として隔離します。

## コンテンツとランの境界

`src/domain/schema.ts` は `schemaVersion: 1` のコンテンツ台帳とラン状態を型・実行時スキーマで定義します。カードの英語入力文字列、効果ID、部活ごとの初期デッキとカードプールは別の項目です。`parseContentRegistry` と `parseRunState` は未登録ID、重複ID、山札・手札等の重複配置、存在しないマップ接続をパス付きエラーとして返します。

効果パラメータの個別意味、キーワードと発火トリガー、入力文字列の正規化・曖昧性、部活の正式名称と固有デッキ内容はまだ確定・実装されていません。テストの `club-a` / `club-b` はスキーマ検証専用の架空fixtureであり、完成コンテンツではありません。

## タイピング入力

`src/domain/typing.ts` は現在の手札から英語入力語を受け取り、キーごとに注入されたゲーム時計を進めてから候補を更新します。誤キー・キーリピート・IME変換中のキーは進捗に反映しません。Escapeまたはフォーカス喪失で途中入力を取り消し、手札から候補が消えた場合も入力を初期化します。期限切れ時に途中入力は発動しません。

完全一致したカードが1枚で、より長い接頭辞候補がなければ発動候補IDを返します。`fire` と `fireball` のような衝突では、短い語の自動発動を止め、暫定のEnter確定を使います。同じ語のカードが複数枚ある場合は自動選択せず、#6で選択UIと解決規則を実装します。#5は入力判定のドメイン処理であり、戦闘UI接続と時間切れ・カード発動の同時刻裁定は #4/#14 で検証します。

同名カードの実体選択と、生存している敵への対象選択は `src/domain/typing.ts` の選択操作で処理します。単体対象のカードで敵が複数いれば、語を完成しても対象が決まるまで発動しません。候補・選択中のカード・選択中の敵は入力状態に残り、UIが表示できます。実際の戦闘HUDとキーボード導線への接続は #14 で行います。

## 決定的な実行部品

`src/domain/random.ts` は全32ビットシードを受け、次の乱数状態を結果と一緒に返します。シャッフルは入力配列を変更しません。`src/domain/clock.ts` は注入された単調時計を使い、描画フレーム数ではなく経過ミリ秒で残り時間を更新します。時計アダプターは非負の整数ミリ秒を返す必要があります。ブラウザの `performance.now()` を使う場合は、アダプター側で整数化します。一時停止中の経過時間は残り時間から差し引きません。

`src/domain/event-queue.ts` は発生予定時刻、同時刻なら登録順にイベントを取り出します。イベント処理中に追加されたイベントも順に処理できます。イベントの中身は後続の効果エンジン #9 が定義します。時間切れとカード発動が同時刻に起きた場合の優先順位は、このキューだけでは決めず、ターン進行 #4 の仕様として扱います。

## カード循環

`src/domain/card-piles.ts` は山札の末尾を一番上としてドローします。足りなければ捨て札を保存可能な乱数状態でシャッフルして山札へ戻し、残りを引きます。手札が空になっても自動ドローしません。ターン終了時はカードごとの保持・捨て札・除外の判断を呼び出し元から渡します。Retain・Ethereal等のキーワード解釈と発火順序は #8/#9 が定義します。手札が変わる操作では途中の入力バッファを取り消します。

`src/domain/card-keywords.ts` はRetain、Ethereal、Innate、使用時Exhaustをカード定義のキーワードIDから解釈します。競合時の優先順位とInnateのドロー枚数への算入は暫定設定です。ターン終了時のカードごとの配置イベントは元の手札順に記録します。

`src/domain/card-operations.ts` は戦闘内での生成・複製・変化・回収・除外を、カード実体IDと配置先を保って処理します。操作イベントは作成/複製→配置、移動→回収の順に返し、後続の発火エンジンが利用できます。戦闘内で生成したカードはランの恒久デッキへ自動追加しません。手札上限は暫定10枚で、ドローとInnateに適用します。カード操作では明示的な上限値を渡します。`null`は上限を強制しない検証・特殊処理用です。

`src/domain/card-triggers.ts` はカードのライフサイクルイベント順、同一イベント内ではトリガー定義順に複数の処理を実行します。効果の具体的な実行器は注入するため、カード・レリックなど別の発火源にも接続できます。イベント対象のカード実体参照を各段階で検査します。

保存状態の検証では、戦闘中の全カード実体が山札・手札・捨て札・除外・効果解決中のいずれか1か所に必ず存在することを確認します。

カード効果の解決中だけ`resolvingPile`へカードを移し、効果が終わってから捨て札または除外に置きます。これにより追加ドローが発動中のカード自身を山札へ戻すことを防ぎます。保存状態の参照検証はこの一時領域も含めます。

## 共通効果の解決

`src/domain/effect-primitives.ts` は攻撃（単体・全体・多段・防御貫通）、ブロック、回復、最大HP変更、状態付与・解除をイベントキューに登録し、時刻と登録順で解決します。効果データから命令への変換はカード・敵Intent等のアダプターが担当します。反撃は各ヒット直後に一度だけ処理し、反撃への再反撃は起こしません。対象消失や死亡による不発はトレースに残します。勝敗が決まった後の未処理イベントは明示的な片付けまでキューに残します。

`src/domain/status-engine.ts` はStrength、Dexterity、Weak、Vulnerable、Frail、Poisonの蓄積・解除・計算補正・ターン境界を一か所で扱います。効果キューの状態付与・解除と攻撃・ブロック補正、プレイヤー／敵の開始・終了時の処理に接続しています。毒はブロックと反撃を通さず、対象のHPを直接減らします。係数と境界時刻は暫定設定です。

## ターン進行

`src/domain/turn-state.ts` は `PLAYER_START → PLAYER_INPUT → PLAYER_END → ENEMY_PHASE` を明示的に遷移させます。開始時は設定枚数をドローして単調時計を開始し、時間切れでは手札の保持・捨て札・除外を呼び出し側のルールで解決します。カード名の入力完了は必須のカード使用処理へ渡し、カードが手札に残る不正な処理を拒否します。敵フェーズの行動解決は #13 が注入し、各Intentの行動が終わってから次ターンに進みます。敵の独立時計や手札切れによる自動補充はありません。

`src/domain/enemy-ai.ts` は敵ごとの固定順・重み付き・条件分岐によるIntent選択と、戦闘順での一度限りの行動を扱います。予告中のIntent IDを実行してから次の予告を選び、召喚された敵はそのフェーズでは行動しません。`src/domain/enemy-intent-effects.ts` は敵用の既定アダプターで、攻撃・防御・回復・状態付与・召喚を効果定義から解決します。AIパターンと効果アダプターは差し替えられます。

`src/domain/time-resource.ts` は残り時間への加算、次ターンへの繰り越し、時間延長ポーション、カードごとのX時間解決を扱います。2秒を1単位とする換算は確定仕様です。30秒上限と既定の端数切り捨ては暫定設定で、Xの丸めと消費方法はカード定義の`xTimePolicy`が上書きします。時間加算は実際の入力時刻まで時計を進めてから行い、期限同時刻の裁定はターン入力と同じ設定に従います。

`src/content/base-cards.ts` は管理シート「基本カード定義」の24枚について、ID・入力語・種別・対象・効果種別を行番号とともに保持します。効果量はシート記載の仮値です。`finish` の条件は #48 の判断待ちで、対象HP50%以下を暫定値としています。各カードのアップグレード内容は原本で未定義のため、`upgradeEffectIds`は未設定です。データ登録だけでは24枚の効果実行を完了したことにはなりません。#12 の後続PRで効果アダプター、対象選択、入力、アップグレードを実装・検証します。

`src/domain/card-effects.ts` はカードを直接タイピングして使うときの共通効果アダプターです。攻撃、ブロック、回復、ドロー、基本の状態付与、時間延長、暫定条件付き攻撃、防御解除までを処理します。手札・捨て札を対象にする操作、持続効果、代償付き効果は #12 の後続PRで接続します。
