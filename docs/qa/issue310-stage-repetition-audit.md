# #310 通常42地点の舞台反復監査

基準は #288 の3 Act×4場所の暫定背景選択と、#286 の地点物体候補。両方とも文芸部・通常12階/Act、seed 42・97、`safe`方針で画面の経路ボタンを押し、イベント/購買/休憩/宝箱/戦闘を経て勝利まで自動操作した。仮時計を使った回帰調査であり、人間のプレイ時間や体感の証拠ではない。背景は #29 未採用候補、#286 のCSS物体も #304 の原画待ちである。

[42地点×2経路の比較ボード](issue310-stage-route-board.html)にはAct/階/地点ID/種類/背景と、#286の物体案を全到着順で並べた。ボードの物体名は**候補との照合**であり、以下の2本の実ラン原記録に#286 runtimeの物体が描画されたという主張ではない。

実寸の #286候補では、購買の棚と休憩の長椅子は背景に対し大きく平面的で、紙/ガッシュ面と濃紺細線の人物・背景との線/影/縮尺が揃っていない。これはCSS仮形状の制約であり #304/#29 の未完了事項。背景の意味を変える小物が画面右側を大きく占めるため、完成形では人物と選択肢を含む 1440×900 / 1024×768 の実画面で再審査する。

## 必要な舞台文法と次の作業

1. **場所IDと小区画IDを分ける。** 現行 `placeId` は校内の地区/階帯として残す。購買・休憩・宝箱・イベントには、その場所へ接続する `subsceneId` と接地アンカーを宣言する。例: 講堂舞台の購買なら舞台裏の備品販売区画へ到着時に入る。ランの地点を変えず、進行中に背景が跳ぶことは避ける。背景だけの差し替えか、建築の見える追加プレートかは #315 で設計判断し、#29 で美術採用を判定する。
2. **地点物体は場所とコンテンツの両方で変える。** #304の原画/IDを `locationKind`、`placeId`、イベント/商品IDから選び、屋内・屋外の接地と昼/夕方の影を揃える。全イベントを掲示板にしない。欠損時は場所と衝突しない簡素なfallbackを用意する。
3. **同じ場所の節目を描く。** 第4帯の3地点とボスが同じ画像のため、ボス到着時だけ建築を保った局所的な「準備済みの場」状態（幕、扉、観測器具、紙の舞台装置など）を別レイヤーで示す。短い行動演出以外の常時派手な照明/揺れは避ける。
4. **時間帯/利用状態を限定的に変える。** Act 1午前→放課後、Act 2午後→夕方、Act 3夕暮れ→終演前の光を、背景レイヤーだけの版付き差分として検討する。色フィルタを人物やUIへ掛けない。4枚×3 Actのコピーを増やしただけで場所数に数えない。
5. **場所タイプの不足を再審査する。** 購買室/保健室/資料保管庫などは独立部屋として必要か、地区内の小区画で足りるかを、経路種類と地理の整合から判断する。次の画像候補を量産する前に、#29の編集可能原本・線/影/パース・人物分離のゲートを満たす制作方法を決める。

この監査だけでは「4地点連続が楽しいか」は決められない。人間の通常ラン、物理iPad、5部活、敵の反復、約60分の体感は未検証。追加の画像候補は、購買/休憩を同じ場所へどう接続するかという #315 の設計判断と #304 の物体原画の境界が未確定なため、今回は制作しない。候補1枚を増やして正式な多様性として数えない。
