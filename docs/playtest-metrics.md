# 実プレイ計測 v0.1

子Issue [#88](https://github.com/sato0825/school-rg/issues/88)・[#146](https://github.com/sato0825/school-rg/issues/146)、親 [#68](https://github.com/sato0825/school-rg/issues/68)。約60分という目標の実測に使うための記録形式です。この実装だけで所要時間や離脱率を測定したことにはなりません。

`?playtest=1` を付けて起動すると、端末内の `school-rg-playtest-v1` に計測を保存します。通常起動では計測しません。ランの開始地点、訪問地点、戦闘ノード、結果、可視状態で操作できる間の経過時間を記録します。戦闘を一時停止した時間とタブが非表示の時間は加算しません。敵フェーズ、マップ選択、購買などの操作時間は含めます。

再読込ではラン固有IDと部活・シード・難度を照合し、保存済み時間から再開します。同じ部活・シードで新しいランを始めても、以前の計測を引き継ぎません。途中から計測を有効にした場合は `partial: true` と表示します。読めない計測データは上書きせず、画面にその状態を表示します。新しいランを明示的に開始すると新しい計測へ切り替わります。

マップ・戦闘・終了画面の「計測JSONを保存」でファイルを出力します。外部送信はありません。JSONは `formatVersion: 2`、ランID、部活、シード、難度、`activeMs`、訪問履歴、戦闘ノードID、勝敗を含みます。`battles` にはAct、敵ID、戦闘開始・終了時の操作時間、HP、ターン数、勝敗を入れます。旧 `formatVersion: 1` と `battles` のない記録も読み込めます。途中から戦闘を計測した場合、その戦闘の `partial: true` は開始前の損失・時間が不明であることを示します。生のキー入力は記録しません。

`contentEvents` は報酬・宝箱・ショップ・イベント画面で実際に提示した候補、選択・スキップ、取得したカード・レリック・ポーション、戦闘で消費・破棄したポーションを記録します。各イベントにはAct、訪問ノード、取得元、種類、候補ID、コンテンツID、操作可能時間を付けます。ショップの在庫提示は購入できるだけの資金があるかを断定しないため `available: null` とし、イベント選択肢は条件による選択可否を記録します。選択と取得は区別し、取得はラン状態の増分から判定します。描画と再読込で同じ候補を重複計上しない安定IDを使います。旧形式から再開した場合や計測を途中で有効にした場合は `contentPartial: true` とし、全提示を観測したランの分母へ入れません。入力した文字、個人情報、任意の自由記述は記録しません。

複数のエクスポートを `node scripts/summarize-playtests.mjs <記録1.json> <記録2.json> ...` に渡すと、同じランIDの途中記録は最新の操作時間へまとめ、5部活別の完了・勝利・敗北・未完了、約60分目標との差、戦闘HP損失とAct別時間をJSONで出します。旧JSONや途中開始した戦闘など、測れない値は中央値から除外し、欠損数を表示します。`incomplete` は保存時に未完了だった意味で、離脱確定ではありません。プレイテストではこれに加えて主観的な難度、不具合、離脱理由を別途収集します。

`encounterVariety` は完了したランの利用可能な戦闘記録から、同じAct内で同じ敵編成に再遭遇した回数を数えます。敵の並び順だけが違う編成は同じものとして扱います。部分記録、途中終了ラン、旧形式で戦闘詳細のないランは分母から外し、`runsWithUsableEncounterRecords` に採用件数を示します。`observedVisits` は完全な記録で終わったランの訪問ノード種別を集計します。どちらもコンテンツへの実際の接触を調べる補助値であり、面白さ、約60分の達成、未完了を離脱とみなす判定には使いません。

`contentExposure` は完了し、全体とコンテンツ記録が共に完全で、イベントIDと訪問ノードが整合するv2ランだけを集計します。部活別・Act別・取得元別に提示、選択、スキップ、取得、消費、破棄を数え、提示の選択可否も `availableOffers`、`unavailableOffers`、`unknownAvailabilityOffers` に分けます。`selectionRate` は選択数÷全提示数を示すため、選択できない候補も分母に入ります。`repeatedOffers` は同一ランの同一Actで同じ種類・コンテンツが再提示された回数です。`runsWithUsableContentRecords` が採用ラン数です。提示されても選ばれない候補や、繰り返し出る候補を調べる補助値であり、実プレイの満足度を代弁しません。

### #68 の実プレイ記録

通常設定で同一ビルド・難度を固定し、5部活×異なる3シードの初回15ランで、勝利・敗北・未完了を問わずJSONを保存します。集計の `medianWonMs` と `rangeWonMs`、`medianActMs` を約60分の目標と照合します。`rangeTerminalMs` は敗北を含む終了ランの幅です。イベント選択肢の再提示はイベントIDと選択肢IDの組で数え、1イベント内に並ぶ異なる選択肢を反復扱いにしません。

JSONには個人名、連絡先、生の打鍵、自由記述を追加しません。主観的難度、迷った操作、不具合、中断理由はランIDに紐づく別の非公開記録で収集し、個人を識別できる情報を含めません。`incomplete` は未完了スナップショットであり離脱確定ではないため、本人が中断したと確認できた件だけを離脱として集計します。15ランの自動集計は初回診断で、実機確認やプレイヤー評価の代わりにはなりません。
