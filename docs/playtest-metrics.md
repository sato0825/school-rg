# 実プレイ計測 v0.1

子Issue [#88](https://github.com/sato0825/school-rg/issues/88)・[#146](https://github.com/sato0825/school-rg/issues/146)、親 [#68](https://github.com/sato0825/school-rg/issues/68)。約60分という目標の実測に使うための記録形式です。この実装だけで所要時間や離脱率を測定したことにはなりません。

`?playtest=1` を付けて起動すると、端末内の `school-rg-playtest-v1` に計測を保存します。通常起動では計測しません。ランの開始地点、訪問地点、戦闘ノード、結果、可視状態で操作できる間の経過時間を記録します。戦闘を一時停止した時間とタブが非表示の時間は加算しません。敵フェーズ、マップ選択、購買などの操作時間は含めます。

再読込ではラン固有IDと部活・シード・難度を照合し、保存済み時間から再開します。同じ部活・シードで新しいランを始めても、以前の計測を引き継ぎません。途中から計測を有効にした場合は `partial: true` と表示します。読めない計測データは上書きせず、画面にその状態を表示します。新しいランを明示的に開始すると新しい計測へ切り替わります。

マップ・戦闘・終了画面の「計測JSONを保存」でファイルを出力します。外部送信はありません。JSONは `formatVersion: 1`、ランID、部活、シード、難度、`activeMs`、訪問履歴、戦闘ノードID、勝敗を含みます。新しい `battles` にはAct、敵ID、戦闘開始・終了時の操作時間、HP、ターン数、勝敗を入れます。古いJSONに `battles` がなくても読み込めます。途中から戦闘を計測した場合、その戦闘の `partial: true` は開始前の損失・時間が不明であることを示します。生のキー入力は記録しません。

複数のエクスポートを `node scripts/summarize-playtests.mjs <記録1.json> <記録2.json> ...` に渡すと、同じランIDの途中記録は最新の操作時間へまとめ、5部活別の完了・勝利・敗北・未完了、約60分目標との差、戦闘HP損失とAct別時間をJSONで出します。旧JSONや途中開始した戦闘など、測れない値は中央値から除外し、欠損数を表示します。`incomplete` は保存時に未完了だった意味で、離脱確定ではありません。プレイテストではこれに加えて主観的な難度、不具合、離脱理由を別途収集します。

`encounterVariety` は完了したランの利用可能な戦闘記録から、同じAct内で同じ敵編成に再遭遇した回数を数えます。敵の並び順だけが違う編成は同じものとして扱います。部分記録、途中終了ラン、旧形式で戦闘詳細のないランは分母から外し、`runsWithUsableEncounterRecords` に採用件数を示します。`observedVisits` は完全な記録で終わったランの訪問ノード種別を集計します。どちらもコンテンツへの実際の接触を調べる補助値であり、面白さ、約60分の達成、未完了を離脱とみなす判定には使いません。
