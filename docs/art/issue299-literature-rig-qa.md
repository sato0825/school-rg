# #299 文芸部 部位別モーション候補 QA（2026-10-31）

## 対象と受入境界

#29/#31 に向けた**文芸部1人の候補**。GameShell の1戦において、待機では呼吸・重心、カード使用ではノートを掲げる腕と上体、被弾では顔・頭・上体・腕・脚を動かす。被弾時は驚いた顔レイヤーへ切り替え、文字を読まなくても攻撃を受けたことを示す。HP減少・カード効果のゲーム状態は既存イベント時計が確定させ、このリグはその確定状態を表示する。敵の行動やゲームロジックを CSS 時間で進めない。

部位画像と 7 層の OpenRaster 原本はそれぞれ保存。`literature-rig-candidate-v2.json` に頭・胴・両腕・両脚・被弾表情の位置、関節、接地、SHAを記録。新しい絵が必要な際は画像の差し替えとマニフェスト更新で既存戦闘ロジックに触れずに交換可能。顔差分のみ画像生成原出力から共通ヘッドキャンバスへ正規化しており、手描きの修正がまだ必要。

## v5 初回読み込み・再描画の根因修正（最終候補証拠）

- v4動画をフレーム検査すると、マップ→戦闘の初回に7部位が個別に読み込まれて人物が欠ける数フレームがあった。`GameShell.showBattle` がタイマー/入力再描画で actor をDOMから外し、リグ画像も再生成していたことが原因。v1/v3/v4動画はこの欠けの記録として保持するが、完成証拠から除外する。
- 修正: `hero-art` の全身像を表示したまま7画像を `decode()` し、全件成功後にリグへ一括切替。失敗時は全身像のままにする。以降は actor/ally-group とリグDOMをステージに接続したまま保持し、入力/タイマー再描画で画像とCSSアニメ位相を再生成しない。
- 800msの部位画像遅延をかけたE2Eで、読み込み中は全身像が不透明・リグが不可視、全件decode後のみ切替を確認。1024/1440の再描画後もリグDOM同一性を確認。1440で低刺激設定のセーブ復帰/再読み込みが成立し、再読込後も7画像が揃い、頭部アニメは停止した。最終ツリーでlint/typecheck、単体119、統合166、ビルド、対象E2E7/7が通過。アート72件/ORAの前回検査は画像・原本が変わっていないため再利用。
- 再録画: `outputs/issue299-literature-{1024,1440}-decoded-idle-card-hit-candidate-v5.webm`。キー入力直後に `card-use`、敵攻撃時に `hit`、HP37/40を機械確認して保存。1440動画の0.6〜0.8秒のマップ→戦闘フレームでは全身像の後に完全なリグが出て、欠けた部位は見えない。2.0〜2.2秒では入力に合わせてノートが上がり、効果表示と足元/人物枠が安定している。
- 低刺激+遅延+再読み込みの動画 `outputs/issue299-literature-1024-quiet-reload-candidate-v1.webm` と静止画 `outputs/issue299-quiet-{loading-portrait,rig-ready,reload-ready}-1024-v1.png` では読み込み中の全身像、揃ったリグ、再読込後の静止姿勢を確認。Web viewportであり実機iPadの合格ではない。
- #327の低刺激QAで見つかった既存GameShell欠落を併せて修正。戦闘前に作られるGameShellでも `data-effects` を初期化し、マップ/報酬オーバーレイへ低刺激状態を維持。統合テスト167/167、型検査、lint、対象E2E7/7、ビルドを最終コードで確認した。
- GameShellの独立レビュー追補: MutationObserverでactor/ally-group/rig/typing-inputそのもの、またはそれを含む祖先の`removedNodes`を監視。タイマー進行、`st`までの部分入力、カード完成/勝利、報酬、経路画面を通して対象の除去記録が0、最後まで`isConnected=true`、入力DOM同一性を確認する。部分入力中はfocusが維持され、残秒が入力前後とも減る。勝利時は入力がdisabledになるためfocus維持を要求しない。低刺激`data-effects=quiet`は報酬/経路で維持する。対象E2Eは8件となる。動画v5はこのDOM差分更新前のものなので、視覚証拠には使えるが入力focus/非detachの最終証拠には使わず、このE2Eを契約証拠とする。
- 入力欄のDOM維持を入れた最終コードで `npm run lint`、`npm run typecheck`、`npm run test:integration`（167/167）、`npm run build`、対象E2E（8/8）が通過。単体119件とアート72件/ORAは対象入力が変わらないため直近の合格を再利用した。1024×768/1440×900の連続録画を `outputs/issue299-literature-{1024,1440}-continuous-input-card-hit-candidate-v6.webm` に保存。録画スクリプトは入力focus、キー直後の`card-use`、敵攻撃の`hit`、終了HP37/40を確認した。両サイズの動画フレームを確認し、初回は全身像から欠けのないリグへ移り、カード入力中の人物・敵・ステージが同じ戦闘画面に残った。動画はWeb viewportであり、実機iPadや人間の初見評価ではない。
