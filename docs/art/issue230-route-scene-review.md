# Issue #230 — 戦闘報酬から校内経路への舞台連続性

## 画面判断

- [PC 1440×900](previews/issue230-route-1440.png) / [iPad相当 1024×768](previews/issue230-route-1024.png)。同一シード42、文芸部、1 Act 1Fの戦闘報酬を1枚選んだ直後。
- 背景URLと人物画像は報酬画面と一致する。経路を右寄せの暗い透過層に置き、人物と校内の通路を左側に残した。現在地と次の候補を経路線・円形ノードで区別する。
- ヘッダはAct/階、HP、所持金、デッキ枚数に絞る。難度・シード・プレイ計測は開閉可能な「ラン情報」に収める。経路層ではヘッダの数値を反復しない。
- 1024pxでは報酬画面と同じ人物位置を維持するため、鞄の左端が画面外に少し切れる。顔、胴、脚、靴、経路ノードは判読可能。人物画像の最終構図は #29 の受け入れ対象。
- iPad実機のタッチと長時間の刺激量は未確認。1024pxはブラウザーの相当幅であり実機合格ではない。

## 動作確認

- 報酬取得→経路表示→保存再読込→キーボードで到達可能な次地点を選択し、次の戦闘へ進む。
- 経路画面は非戦闘状態でタイマー/タイピング欄を持たない。低刺激設定ではブラーを止めても現在地・候補の区別を保つ。
- 疎な経路とAct境界は既存の `MapNode.nextIds` と `availableRunNodes` に従い、描画側で接続を追加しない。
