## 状態と実装の接続

`RunSession.screen` は `treasure`、`shop`、`rest`、`event` をすでに持ち、既存処理で宝箱の一品/スキップ、売買/削除/退出、回復/強化、イベントの条件・対象選択・戦闘分岐を扱う。`save.ts` は地点に対応する `run.shop`/`run.treasure`/`run.event` と画面の整合を検証する。現在の `app.ts` は4地点で `gameShell = null` に戻すため、#261 安定後の統合ではこの分岐と `run-view.ts` の旧 `shell()` 全面置換を変える必要がある。ロジック・保存形式をUI都合で変更しない。

1. 地点到着時に `scene` と物体だけ入れ替え、stage・人物・ヘッダ・入力アンカーを破棄しない。地点内の棚切替や購入では背景を切り替えない。
2. 戦闘時計は地点で進めない。現在のターン時間は保存済みの戦闘規則に従い、#223 の閲覧時計判断を上書きしない。
3. データから選択肢を作り、見本の品名・値を本編に固定しない。満枠、金額不足、購入済み、強化対象なし、イベント条件未達は物体の状態と短い理由で判別できるようにする。
4. タッチ対象を最低44×44 CSS pxにし、Tab/Enter/Space/IME とフォーカス戻りを検証する。非表示の棚・対象カード・結果を読み上げ順から外し、結果を `role=status` 等で通知する。
5. 本編 E2E は経路→4地点→経路/戦闘/敗北、保存→再読込、PC/iPad相当で実施する。ノード確定時のみ背景更新を確認する。実機iPad未実施を実機合格と記載しない。

## この候補で未解決のこと

- CSS 小物は構図確認用の仮形状で、統一絵柄の最終制作ではない。背景も全地点で同じ仮アトリウムを使っており、各地点の校内空間の差は採用前に描き分ける。
- この静的な選択肢はクリックもキーボード操作もできない。各種不足/対象指定/購入後/イベント長文の実寸状態、演出と音、1〜3人味方編成の重なり、実機iPad、初見理解は未検証。
- 現行 #261 自体が視覚統合中の Draft で、後続の位置契約はその安定HEADに合わせて再評価する。
