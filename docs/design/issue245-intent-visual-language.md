# Issue #245 — 敵の強さと次行動を読む文法（候補）

親: #243。孤立した実寸デザイン候補: [issue245-intent-prototype.html](issue245-intent-prototype.html)。本番UIへの採用前に#243のカード・レリック・レアリティを含む総合設計と照合する。

## 根本原因

現行 `src/ui/battle-view.ts` は `intent.effectIds[0]` の `amount` だけをチケットへ表示する。エンジンは全 `effectIds` を配列順に処理するため、モップの「攻撃3×2→防御4」、コイルの「防御4→攻撃3」、時計の「力+1→防御5」は後半や回数を読み取れない。毒・脆弱・召喚も対象と結果が曖昧。「複合」という分類は予告の説明になっていない。

## 読み取り階層

1. **遭遇区分**: 地点の `kind` から通常/強敵/ボスを示す。架空の脅威スコアは付けない。形と短い語で区別し、色だけに依存しない。
2. **生存力**: 敵の足元に名前、HPゲージ＋現在/最大、Block、状態を置く。HP最大値だけで強さを判断させない。
3. **今回の行動**: 名前・HPと同じ足元プレートに全効果を実行順の絵記号＋値で `›` により連ねる。上部に浮く説明チケットは置かない。攻撃は1発値×回数、Blockは獲得値、状態は名称＋増減、召喚は種類と数。各効果の下に対象を表す方向記号を置く。`↙` は左側の味方、`◎` はその敵自身、`↗` は敵側の追加対象を示す。方向記号だけでは意味が伝わらない人のため、選択時の詳細と読み上げでは対象名を明示する。
4. **詳しい意味**: 敵を選択/フォーカスした時だけIntent固有名と全効果を順番に展開する。スクリーンリーダーは全効果・対象・回数を読み上げる。

攻撃=斜線、防御=盾、強化=上矢印、状態異常=下矢印、召喚=重なる紙片のSVG記号を使う。同じ意味には全敵・全Actで同じ形を使い、色は補助的に使う。

| 効果データ | 表示 | 対象 |
| --- | --- | --- |
| `damage {amount:3,hits:2}` | 攻撃 `3×2` | 味方 |
| `block {amount:4}` | 盾 `+4` | 自分 |
| `status {strength,delta:1}` | 上矢印 `力+1` | 自分 |
| `status {poison,delta:1,target:player}` | 下矢印 `毒+1` | 味方 |
| `status {vulnerable,delta:1,target:player}` | 下矢印 `脆弱+1` | 味方 |
| `summon {enemyId}` | 紙片 `+1` | 敵側 |
| `heal {amount}` | 回復記号 `+値` | 指定対象 |

実装時は `Intent.category` や最初の効果で文法を決めず、公開された `intent.effectIds` **全件**をエンジンと同じ順序で解釈する。プレイヤーBlockを引いた「HP予想減少」は安易に表示しない。攻撃値は `modifiedAttackAmount`、Block獲得は `modifiedBlockAmount` と同じ現在状態・設定で算出する。前効果が後効果を変える場合は順序どおりの状態で再計算し、カード/ポーションによる状態変化後に予告を更新する。互換テストは本番実装Issueの条件。

## 密集編成・低刺激・限界

5体では各敵の足元プレートに名前・HP・Block・予告を統合する。プレートの輪郭は遭遇区分で変わり、頭上に説明チケットを並べない。選択中の敵だけ詳細を開く。プロトタイプの5体は異なるActを混ぜた**レイアウト負荷テスト**であり、実際の遭遇表を変更しない。敵の行動順は `combat.enemies` の順序。低刺激では動き・発光を抑えても位置・形・数値・順序を残す。

## 採用ゲート

- PC 1440×900・iPad相当1024×768で1/2/5体を表示し、HP・予告・対象が人物/敵絵を隠さない。予告とHPの実寸画面は `previews/` を参照。
- 攻撃3×2→防御4、力+1→防御5、毒/脆弱、召喚を初見の人が説明なしに読み取れるか実観察する。誤読した場合は記号/値/対象を修正。
- 各Intentの画面予告とエンジンの実行traceが一致する自動テストを作る。状態修飾、Block、複数敵、保存復帰を含める。
- 本プロトタイプはUX理解テスト・実機iPad・最終アート受入を通っておらず、完成UIではない。
