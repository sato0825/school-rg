# #242 ゲーム画面の一体設計 — レビュー用

敵Intentと手札を読み、限られた秒数で綴り・順序・対象を選び、カード発動の結果を見て次の入力を決め、報酬・経路・部活デッキを組み替え3 Act進む。画面はこの判断が毎秒追えるように、人物と敵を校内の舞台に置き、カードを手元の実物、経路と記録を校内の紙として扱う。

## 実寸モック

`issue242-game-screen.html` は保存データや本編に接続しない独立した画面案。`?scene=combat|impact|reward|route|detail|relic|last-hit|defeat`、`&quiet=1`（動きなし）、`&bg=paint`（ガッシュ廊下候補）を指定できる。直接キー入力の簡易演出は画面案の操作確認用であり、ゲームの入力判定・敵AI・報酬確定を実装したものではない。

## 画面の読み順と役割

1. 敵の絵・足元のHP/格/Intent。Intentは効果の順序、値、対象方向を同じ敵プレート内で読む。区分と状態は同じ情報に混ぜず別の印にする。多敵時にはプレートを敵の足元へ結び、画面上端へ説明票を増やさない。#245の全effectIds文法を採用する前提で、現在の1敵モックは攻撃6×2→防御4だけを例示する。
2. 手札のカード固有絵、綴り、効果。絵は瞬間認識、綴りは入力、効果アイコン＋値は判断に使う。カード種別（攻撃・技能・持続）とレアリティを別軸で符号化する。現モックの Common/Uncommon/Rare 割当は仮提案であり仕様ではない。`data-art-id` と `data-art-version` を交換点としておく。
3. 中央下の秒数と進行線。タイプされた綴りを手札の候補に直接反映する。フォームの入力欄を置かない。誤キー無視、IME入力、候補競合、時間切れ競合は本編の入力実装で検証する。
4. 結果は対象の近くに出す。発動時は敵HPの減少と局所軌跡、敗北時は主人公のポーズとHP 0で表す。ステージ全体の揺れを恒常的な通知にしない。
5. 戦闘後は同じ舞台の上でカードを選び、経路は薄い校内紙面として重ねる。背景・人物は残す。経路モックは1–3/15Fの抜粋で、3階だけのActを意味しない。本編の全階層、到達可能性、スクロールと分岐は別途データ検証が必要。
6. 最後の被弾→敗北の画面では主人公を消さず、敵の位置も残し、校内ノート状の結果札を右に置く。既存hit候補を仮用した。専用敗北ポーズ、静止残像量、再挑戦の実際の動線は敗北演出Issueで評価する。

## アート判断

既存背景 `src/assets/stage-hallway-v1.png` は床の反射と細部が写実寄りで、人物の2D線画とやや離れる。新規候補 `issue242-assets/corridor-gouache-candidate-v1.png` は反射を抑え、薄い紙/ガッシュ面と濃紺の細線に近い。人物と敵を重ねた実寸では新規候補のほうが同一世界に見える。ただし学校背景の最終採用には #249 のアトリウム候補、複数背景への展開、描画の一貫性を比較する。

現モックのカード8点とレリック1点はレイアウト確認用の生成候補で、いずれも正式採用していない。`jot` には擬似筆記、カードごとの質感差、レリックには縮小時の輪郭不足がある。#246の紙/ガッシュ・濃紺輪郭・低彩度涼色のアートバイブルと候補を優先比較し、全カード84点、レリック11点、ポーション6点の図像とレアリティを制作・検収する。テンプレートの `artId` / `version`、安全な画角、手札縮小・報酬サイズでの読みやすさ、カード種別とレアリティの独立符号を品質ゲートにする。

## 判定

- **画面案として成立**: PC/iPad相当で、カード名直接入力、敵の次手、HPと状態、山札/捨て札、報酬、経路、詳細、レリック、敗北の情報配置を実寸で比較できる。
- **未検証**: 実機iPad、初見の中学生/感覚過敏ユーザーによる理解、1–5敵/1–3味方での可読性、実際の時間制限とIME、入力中の詳細表示と休止、暗部/色覚差、アニメーション品質。
- **未完成**: 本編UI統合、全Act/5部活の固有絵、経路全階、効果の全種類、選択対象と多敵プレート、敗北専用ポーズ、音と振動の強度設定。モックのクリックは保存状態を変更しない。
