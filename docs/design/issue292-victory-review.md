# #292 勝利画面の実装レビュー

## 実画面

- [1024 × 768、文芸部の保存済み勝利・接地調整後](../art/previews/issue292-victory-1024-candidate-v2.png)
- [1440 × 900、文芸部の保存済み勝利・接地調整後](../art/previews/issue292-victory-1440-candidate-v2.png)
- [1024 × 768、シード42のタイピング操作による3 Act完走・接地調整後](../art/previews/issue292-victory-typed-3act-1024-v2.png)

画面と人物の DOM は最終戦から保持する。最後のカードの局所演出が終わってから `settleRunCombat` が `won` へ遷移する。実戦闘からの遷移では、最後の敵の退場 0–340ms → 人物の達成姿勢 180–520ms → 紙の記録 500–820ms → Act 印 820–1420ms の順に局所表示する。保存復帰・低刺激・OSの動き軽減ではこの待ちを挟まず静止画を表示する。舞台全体の揺れと閃光は使わない。

人物アンカーの DOM と座標は保持し、勝利姿の画像だけ足元を18px下げて局所影を濃くした。入力欄は無効化し、戦闘時計は終了済みで再開しない。Act 1–3 の達成、残り HP、難度、次ランと履歴を表示する。

表示した人物は、5部活の既存の**発動ポーズ候補**であり、正式な勝利絵ではない。差し替えは `victoryCandidateByClubId` のみに閉じ、ゲーム状態・セーブ形式に入れない。0.42秒の局所的な姿勢切替は連続したキャラクターアニメーションの完成ではない。#29 と #31 の編集可能原本、フレーム間の同一性、5人の専用勝利演技は残る。

## 検証

- Lint、型検査、production build 合格。
- 5部活 × 1024/1440 の11個の勝利状態 E2E、ラン履歴2件は合格。低刺激時の人物アニメーション停止、勝利中の入力無効化、保存復帰後の舞台/人物座標、履歴の重複なしを含む。
- シード42のタイピング操作で3 Actを完走し、最終戦の `.stage`、`.ally-slot`、`.typing-input` の DOM 同一性、敵→人物→ノートのCSS時間順、全舞台アニメーションなし、履歴1件、難度解放を確認。初回は旧テストヘルパーが最終ボスにも報酬画面を待って失敗した。期待終了先を `.run-result` へ修正して対象テストが合格した。局所時間順の検証では、戦闘用画像に残った inline `animation-delay:0ms` を検出して解除した。
- 1024/1440実寸画像を目視。結果の主要操作は画面内、横スクロールなし。勝利時に敵像は薄く残る。旧画像は初期候補として残し、v2画像を接地調整後の受入候補とする。最終採用前に人物/敵/舞台の光と接地、勝利専用動作を審査する。

未検証: 実機 iPad、初見プレイヤーの勝利/次操作の理解、専用勝利絵の正式採用、5部活それぞれの3 Act実プレイ、音の実機聴感。#261 の GameShell と #268 の敗北ラインへ積み上げ統合するまで本編 main には入らない。
