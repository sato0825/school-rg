# #316 カード取得頻度の視覚文法・仮表示実験

**状態: 未採用の表示実験。** [#247](https://github.com/sato0825/school-rg/issues/247) でレアリティの意味、段階数、84枚への配分、ドロップ率は決まっていない。このディレクトリの `visualProfile` はデモ用の表示スロットだけに割り当て、ゲームのカード定義・報酬抽選・セーブ形式には入れない。

## 根拠と狙い

- [#247](https://github.com/sato0825/school-rg/issues/247) と[設計書 v0.1](https://docs.google.com/document/d/1Z4eGdsTD1q9eu6O1czWZs96LPDSavSnT1zncXpa5uRI/edit)はレアリティをカード名・効果・部活などと分離している。管理[Sheet](https://docs.google.com/spreadsheets/d/1R9pxJ1cgfBqbuWvw-IqMqFN-hVuGwfaRa2LFVuhQ4tI/edit)の確認済み基礎カード24件は `未設定`。[#68](https://github.com/sato0825/school-rg/issues/68) の3 Act・5部活の報酬バランス検証より前に配分を確定しない。
- 仮説は「取得機会の頻度」であり、強さやカード種別を表さない。画面の上端右側に、形（輪・菱形・星形）＋枠の質感（単線・切欠・二重）＋短語（よく出る・ときどき・まれ）を同じ順で置く。色は補助で、彩度を抑える。
- 戦闘中の主情報は入力語と効果、報酬時の主情報は絵・入力語・効果と取得選択。頻度表示はその次の階層に置く。発光、常時アニメーション、音は使わない。

## 開き方・置換境界

`docs/design/issue316/` をリポジトリルートから静的 HTTP サーバで公開し、`index.html` を開く。上段ボタンで戦闘手札／報酬、通常／白黒／低刺激、絵のみ／文字のみを切り替える。`visual-config.json` の `profiles` が表示文法、`fixtureOnly` がデモ用割当で、後者は正式カードレアリティの提案ではない。#247の決定後は `profiles` の見た目と正式な意味を改めて対応づける。

背景は #261 の同シードの画面候補を参照用に固定したもの。実ゲームの操作・タイマー・報酬抽選の挙動を検証する画面ではない。絵は既存の未採用候補を原本のまま参照し、絵自体へレアリティ記号を焼き込まない。

## 検証結果

`node docs/design/issue316/qa.mjs` で 1024×768 と 1440×900 の計12画面を取得。手札は 140×160 / 170×160、報酬は CSS 185×247（左右は2度傾けるため見かけ上193×253）。全画面で画像ロード、横はみ出しなし、入力語／効果およびカード種／頻度表示の非重複を確認。`eslint` は `prototype.js` と `qa.mjs` に合格。白黒でも3形・3枠を区別でき、低刺激では彩度を落としても文言は保持した。スクリーンショット `qa-v2-*` が最終版、`qa-*` は報酬背景の旧カードが透けて見えた初版の比較証拠。

絵だけでは各カードの行為の物体を識別できる一方、形の意味を初見で確定できない。文字だけなら入力語・効果・仮の頻度語を読めるが、行為の瞬時把握は弱くなる。図像と文字が相互補完することを確認するため、実際のプレイヤーで初見理解・色覚条件・低刺激設定を検証する必要がある。今回は静止モックの視認性検査であり、正式採用、実ゲーム統合、実機 iPad QA、アクセシビリティ合格、全カード配分は未完了。

## 採用前の判断ゲート

1. #247で意味・段階数・割当基準・表示語を確定し、仮の `fixtureOnly` を正式データへ混入させない。
2. #68で3 Act・5部活の報酬分布を検証し、見た目の段階と実際の頻度が一致することを確認する。
3. #261の実ランタイム手札・報酬へ切替可能な表示部品として接続し、1024/1440と実機 iPad で、入力語・効果・絵の視認性と意味の初見理解を再検査する。
