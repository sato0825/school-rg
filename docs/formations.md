# 複数敵Encounter候補（Issue #104）

Encounterプールは従来の敵ID文字列に加え、編成IDと1〜5体の敵ID列を持てる。ラン開始時に編成順どおり `enemy-1` からインスタンスを作り、それぞれのIntentを選択する。効果、対象選択、保存、画面配置は同じ戦闘システムを使う。1体の既存データとイベント戦闘の単体敵は変更不要。

Act 1の強敵候補「廊下の見回り＋答案の切れ端」を暫定データとして追加した。切れ端はHP12、攻撃2の仮値。編成選択を固定するため現時点のAct 1強敵プールはこの1編成のみで、出現頻度や難度の完成値ではない。画像は両敵とも共通の仮素材で、最終的な敵デザインではない。

複数敵のHP、攻撃順、単体対象の選択、全体攻撃、他の部活での対応を実操作と回帰テストで確認する。正式な編成量、敵アート、約60分のバランスは #29/#68 に残す。

## 実画面

通常ランのAct 1最初の強敵ノードを開き、修正後の[1440×900](content/previews/issue104-formation-desktop-revised-20261031.png)と[390×844](content/previews/issue104-formation-narrow-revised-20261031.png)を保存した。[修正前のデスクトップ](content/previews/issue104-formation-desktop-20261031.png)と[狭幅](content/previews/issue104-formation-narrow-20261031.png)では2体の枠とIntent・HP表示が重なったため、位置と狭幅の表示幅を調整した。修正後は敵枠、Intent、HP表示が互いに重ならず、入力帯も侵食しない。狭幅では敵の絵が小さく、最終アートの識別性は未検証。両敵に同じ仮画像を使っているため、見た目の差も未完成。

カード名 `strike` を入力した後に右の敵を選択し、HPが12→6で左の敵は30のままであることを確認した。続いて `sweep` を入力し、両方のHPが減ることと、戦闘が勝利まで進むことをE2Eで確認した。敵フェーズの行動順は結合テストで確認した。
